# v1.2.0: approved click-pacing improvement

Release-preparation candidate, version 1.2.0/code 4, signing identity unchanged. All eight Vivo-to-Ubuntu hardware checks passed as reported by the user. The v1.1.0 release/tag is untouched; final commit/tag/publication await approval.

Dedicated mouse buttons use physical finger DOWN/UP timing. Recognized touchpad double-taps instead generate four synthetic edges at 20 ms intervals (40 ms press-to-press). Slower taps outside the recognition window produce independently deferred clicks with a larger natural interval. This difference plausibly explains why slower tapping or a third click can work while the synthesized pair does not. Host filtering or compressed Bluetooth submission remains unproven without host event capture.

This experiment changes only TouchpadView's synthetic click-edge interval from 20 to 40 ms, using a named constant in TouchpadGestures. A recognized pair now nominally emits DOWN/UP/DOWN/UP at offsets 0/40/80/120 ms. First single-click DOWN remains 120 ms after UP; release completes 20 ms later than before. Right-tap synthetic release also uses the new interval. Dedicated buttons and drag press/release remain immediate.

The 120 ms first-UP/second-DOWN recognition limit is intentionally unchanged. Extending the same value would delay single-click delivery. Separating those clocks while preserving late double-tap dragging requires more state and can allow an already-delivered first click plus a drag press to trigger host double-click actions; that is not introduced in this one-variable experiment. Taps at/above 120 ms still produce independent clicks. A third physical tap produces one additional click, not a duplicated double-click sequence.

Tests cover rapid taps, 119/120/121 ms and moderate boundaries, triple-tap counts, HID button bytes, single-click deadline, late UI dispatch, drag hold/movement and cancellation. A fake stalled worker demonstrates that correct UI emission spacing cannot guarantee Bluetooth submission spacing. No sleeps, transport scheduler changes, queue caps, high-frequency logging or Ubuntu settings changes are included.

## Vivo → Ubuntu gate

Install with `adb install -r app/build/outputs/apk/debug/app-debug.apk`, preserving settings/bonds. Keep verbose input logs off. At the same sensitivity, compare ten rapid doubles and ten moderate doubles on a file/folder and title bar. Note successful actions and any cursor drift. Test a triple-tap to detect extra actions. Then check single-click responsiveness, stationary double-tap hold, moving double-tap drag, browser-tab drag, dedicated-button drag, two-finger right-click, scrolling, zoom and keyboard. Cancel/interruption must leave no held button.

If failures remain, compare raw Ubuntu BTN_LEFT edges with libinput's processed events; record four transitions, timing and any X/Y movement. Android request acceptance alone does not establish delivery. Do not change host settings to mask failure.
